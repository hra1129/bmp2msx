# EPAL 記録の 5bit 吸着化 実装メモ

2026-11-07。作者判断「EPAL のときは 3bit 吸着ではなく 5bit 吸着に変える」
（hguard 納品 §6 作者確認事項2、および dedup 納品で実害が証明された
3bit 引き戻し問題への確定回答）を実装した。土台は dedup 納品時点の
ツリー（パレットUI ＋ hguard ＋ GUI ＋ fix1 ＋ dedup 適用済み）。

## 1. 変更内容

CreatePal の3コピー（`source/WndProc.cpp`、`linux/wx/gui_convert.cpp`、
`linux/src/convert_run.cpp`）の EPAL-N 分岐（cnvIsEpalMode 系）に、
同一の変更を入れた。

- **反映ループで AUTO 項目を無条件に 5bit 記録する**。従来は
  EpalHGuard ON のときだけだった 5bit 記録
  （`color_palette_epal[i] = (Pal[j] の各チャンネル *31+127)/255` し、
  `keep_epal[i] = true`）を、OFF でも常に行う。これにより最終段の
  再導出ループは AUTO 項目を上書きしなくなり、選択が持つ 5bit 精度が
  そのまま記録される。`color_palette`（3bit 側）は従来どおり最近傍の
  3bit 近似を受ける。
- それに伴い、記録の可否だけを担っていた局所変数 `hguard_on`
  （宣言と `hguard_on = true;` の代入）は3コピーとも撤去した。
  特徴色改善ステップ自体は `Mode->EpalHGuard` で直接ゲートされており、
  意味は変わらない。等価性は §3.2 の ON バイト一致で実証した。
- PALEN_USE／固定項目には触れていない。固定項目の 5bit マスター判定
  （パレットUI納品の EpalIsEdited 機構）と最終段の導出規則は無変更。
- 非 EPAL モードは無変更（§3.3 でバイト一致を確認）。
- EpalHGuard オプションの意味は従来どおり（土台選択＝Wu＋k-means＋
  ガード か、メディアンカットか）。変わるのは記録段だけである。

検証用ツリー（phase5wx）の convert_run.cpp は env 実験フック入りの
変種だが、同じ変更をそちらにも入れてある。納品する
`linux/src/convert_run.cpp` は従来どおりフック無しの納品ファイルに
本変更だけを足したもので、両ビルドの出力一致も確認した（§3.2）。

## 2. SC8P の判定

**SC8P は変更不要（既に 5bit 記録）**。SC8P 分岐は選択結果を
color_palette（3bit）を経由せず、末尾で全256項目を直接
`(v*31+127)/255` で color_palette_epal に記録している（3コピーとも）。
実際、OFF バッテリでも 8p／8p-256 の出力（.SRP／.BAS）は
変更前後でバイト一致した。

## 3. 検証

作者設定＝SC5P、リサイズ on、アンチエイリアス、サイズモード msx、
拡散 on、係数 0.430、cuterr 0、ディザなし、タイル on。
真 SSE は 555 ヒストグラム上の無重み指標（従来定義）。

### 3.1 OFF: 5bit 記録の効果（真 SSE）

| 題材 | BEFORE（3bit 吸着） | AFTER（5bit 記録） | 変化 |
|---|---:|---:|---:|
| fox | 615,860 | 501,053 | −18.6% |
| birds | 181,730 | 50,581 | −72.2% |
| synth | 339,736 | 287,245 | −15.5% |
| grad | 768,290 | 667,270 | −13.1% |
| photo | 1,708,927 | 1,478,384 | −13.5% |
| OIP | 393,623 | 327,878 | −16.7% |

- BEFORE のパレットは全チャンネルが 8 段階グリッド
  {0,4,9,13,18,22,27,31} 上（off-grid 0）、AFTER は題材ごとに
  22〜42 チャンネルがグリッド外の真の 5bit 値になった。
- grad／photo の AFTER は、hguard 納品メモ §2.2 の段階表にある
  5bit 記録前提のメディアンカット値（667,270／1,478,384）と一致し、
  試作時代の nosnap 測定が実パイプラインで再現されたことを裏付ける。
- birds の改善幅が特に大きいのは、鳥の色 (4,5,9) 付近が 3bit セルへ
  潰れる損失が支配的だったため。

### 3.2 ON: バイト一致

- 題材6件（fox／birds／synth／grad／photo／OIP）の全出力
  （.SRF／.CSV／.BAS）が変更前後でバイト一致。作業ツリー版・
  納品ファイル版の両ビルドで確認し、両ビルド間も一致。
- 回帰バッテリ（3画像 × 24モード × 3出力＝534ファイル）に
  `--epal-hguard on` を付けて実行しても 534/534 バイト一致。

### 3.3 OFF バッテリ: 非 EPAL はバイト一致

同じバッテリ（デフォルト設定、EpalHGuard OFF）で変化したのは
EPAL-N モードの 54 ディレクトリ（grad／photo の 2p〜7p 系すべてと
prim の 6p 系、ファイル数で 144/534）だけだった。

- クラシックモード（2,3,5,6,7,8,10,12 と各 -256）は全てバイト一致。
- SC8P（8p／8p-256）もバイト一致（§2 のとおり元々 5bit 記録）。
- 変化した EPAL-N パレットは、BEFORE は全チャンネルがグリッド上、
  AFTER はグリッド外の値を含み、色数は全モードで満杯
  （16/16、6p 系は 4/4）だった。

### 3.4 固定パレット

- **CLI の custom 指定**（synth、項目0＝黒・項目5＝白を固定）:
  固定項目の記録値は OFF／ON とも変更前後で同一。OFF では
  AUTO 項目だけが変わった（13/16）。
- **5bit マスター状態の B2M**（項目0＝(10,20,30) を 5bit 編集状態で
  固定、項目5＝3bit 白。生成用小プログラムで SETTING を書き出し
  `--load-setting` で投入）: 項目0 は BEFORE／AFTER とも
  (10,20,30) のまま記録され（マスターでない項目なら導出値
  (9,18,31) に潰れる値）、項目5 は (31,31,31) で不変。
  OIP／synth 両題材、OFF／ON とも固定項目は同一で、ON は
  AUTO 項目も含め完全一致した。

### 3.5 dedup との関係

- OIP の OFF は AFTER も 16 色ユニークを維持（dedup の効果は
  壊れていない）。
- 含意: dedup 後処理（Convert.cpp、今回無変更）は EpalN について
  「記録形式」＝従来の 3bit 引き戻し変換で重複を判定していた。
  記録が真の 5bit になった今、その判定は必要条件より強い
  （引き戻しセルが分かれていれば 5bit でも当然別）ため、
  保守側に倒れたまま重複ゼロを保証する。Wu／256 の判定は
  元々 5bit そのもので不変。

### 3.6 ビルド

- Linux CLI: ビルド・リンク成功（作業ツリー版・納品ファイル版とも）。
- wx GUI: この環境には wxWidgets 3.2 があり、`make gui` で
  編集後の gui_convert.cpp を含めてビルド・リンク成功した
  （従来メモの「wx ヘッダ欠落」は今回の環境では解消していた）。
- Windows（Visual Studio）ビルドはこの環境では実行できないため
  未確認。変更は CreatePal の EPAL-N 分岐内だけで、他ファイル・
  ヘッダ・シグネチャに変更はない。

## 4. 残る作者判断・オープン点

- 本変更で hguard 納品 §6 の確認事項2（ON 時 5bit 記録の解釈）は
  「EPAL では常に 5bit 記録」として確定・一般化された。
- 同 §6 の確認事項3（birds 型ケースのガード許容 +723）は従来どおり
  作者判断として残る。
- OFF で「全色が1つの記録セルに収まる画像では重複が残る」という
  dedup 納品 §5 の限界は、記録セルが 5bit 化されたことで
  事実上解消する（5bit で別色なら別々に記録される）。

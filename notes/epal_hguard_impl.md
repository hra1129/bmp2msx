# EPAL 改善選択 (EpalHGuard) 実装メモ

2026-11-07。土台はパレットUI納品時点のツリー。試作の経緯は
`epal_refine_proto.md` / `epal_accent_proto.md` / `epal_uvsaliency_proto.md` /
`epal_uvseed_proto.md` / `epal_sqrt_hist_proto.md` を参照。

## 1. 概要

`SETTING.EpalHGuard` (デフォルト OFF) を追加した。ON のとき EPAL の
自動選択は次の3段構成になる。

1. **土台選択: Wu + k-means** — Wu の分散最適ボックス分割で初期パレットを
   作り、k-means (LBG) で生カウント SSE を磨く (`cnvGetPaletteEpalWu`)。
2. **特徴色の提案: h ドメイン** — UVY 応答から
   `h(c) = sqrt(n(c)) + b(c)` を作り、悪くサービスされている色クラスタを
   候補として提案する。
3. **受理判定: 真 SSE ガード** — 候補と既存色の入れ替えは、真の
   (無重み) SSE が増えない場合だけ受理する (`cnvEpalImprovePalette`)。

OFF のときは従来のメディアンカット経路がそのまま動き、
全モード回帰バッチ (3画像 × 24モード × 3パレット出力 = 534ファイル) が
変更前とバイト一致する (検証 §4.1)。

## 2. 設計

### 2.1 スイッチとファイル互換

- `SETTING` 構造体の**末尾**に `bool EpalHGuard` を追加
  (`color_palette_epal` の追加時と同じ方式)。設定ファイル読み込みは
  `GetDefCfg` (memset 0 + 既定値) の後に `sizeof(SETTING)` を読むため、
  旧ファイルでは末尾が 0 = OFF になって互換が保たれる。新ファイルの
  末尾を旧ビルドが読んでも無視されるだけである。
- `GetDefCfg` に `Mode->EpalHGuard = false;` の明示初期化も追加。
- CLI フラグ `--epal-hguard on|off` を追加。`--show-settings` の表示に
  `epal_hguard=` を追加。
- GUI のチェックボックスは未実装 (§6 オープン点1)。SETTING の保持と
  変換への反映は済んでいる。

### 2.2 土台選択 `cnvGetPaletteEpalWu` (Convert.cpp)

- 引数・除外規則は `cnvGetPaletteEpalN` と同じ (FourceZero 除外、
  固定色のビンはゼロ化され、固定色が中心になることはない)。
  使用色数が上限以下なら「多い順にそのまま採用」も EpalN と同じ分岐。
- **Wu 法**: 555 ヒストグラムのモーメント (Σn、Σnr/Σng/Σnb、
  Σn(r²+g²+b²)) からボックス内二乗誤差 SSD を定数時間で評価する。
  SSD 最大のボックスを、2分割後の Q 合計
  (Q = ((Σnr)²+(Σng)²+(Σnb)²)/Σn) が最大になる軸・位置で割る
  (Q 合計の最大化は合計 SSD の最小化と等しい)。同点の場合は最初に
  見つけた方を採る決定的動作。
- **k-means (LBG)**: Wu のボックス平均 (実数) を種に、
  「最も近い中心への割り当て → 画素数重み付き平均で中心を更新」を
  割り当てが変わらなくなるまで (上限100回) 繰り返す。空になった
  クラスタは中心を据え置く。同距離は小さい添字優先。最終パレットは
  中心を丸めたもの。
- EPAL-N (16色/4色) と SC8P (256色) の両方で、ON のときはこの土台を
  使う (SC8P は従来 `cnvGetPalette256` が土台だった)。

段階別の実測 (作者設定・SC5P、真 SSE):

| 題材 | メディアンカット | Wu | Wu+k-means |
|---|---:|---:|---:|
| synth (星) | 352,981 | 151,594 | 146,307 |
| birds (鳥) | 24,134 | 24,004 | 23,477 |
| fox | 514,351 | 428,508 | 395,859 |
| grad | 667,270 | 686,121 | 613,419 |
| photo | 1,478,384 | 1,290,306 | 1,194,794 |

- Wu は synth で −57% と大きく効く。grad では Wu 単独がメディアン
  カットより悪化する (686,121 > 667,270): 一様なランプでは分散分割の
  箱平均が不利になるためで、k-means が 613,419 まで改善して逆転する。
  土台は Wu+k-means の組として評価すべきことの実例。

### 2.3 特徴色改善 `cnvEpalImprovePalette` (Convert.cpp)

土台パレット (メディアンカットでも Wu でもよい) を受け取る独立した
後処理として実装した。CreatePal の各コピーからは、土台選択の直後に
呼ばれる。

- **UVY 応答**: 色差マグニチュード M=|(U,V)| と輝度 Y のハイパス応答
  (半径2のボックスぼかしとの絶対差) を、それぞれデッドゾーン
  (色差 2.0 / 輝度 6.0) を引いて p99 で [0,1] に正規化し、
  sqrt(nM² + nY²) を応答とする (試作3の UVY、そのまま)。
- **h(c) = sqrt(n(c)) + k・b(c)、k=1**: b(c) はビン別の応答合計で、
  全画素が応答 1.0 のビンでは b(c) = n(c) になる画素等価の正規化。
  k=1 は試作4のスイープ (k=0/0.5/1/2/4) で、星が入り・最大ビン
  (レターボックス黒) が壊れず・写真の悪化が最小だった値。
- **提案**: スコア h・d1 (d1 = 現在のパレットまでの二乗距離) の大きい
  ビンを種に、強応答 (応答 ≥ 0.25) 画素のうち色空間で種から半径5
  以内のクラスタを取り、応答重み付き重心を候補色とする。支持画素
  8 以上が条件。候補を単一ビンにしないのは、鳥の特徴が16ビンに
  割れてビン種では届かなかった試作 (シードミント) の教訓。
- **押し出しと受理**: 候補を入れる代わりに外す色は、ΔJ (h ドメインの
  増分) の小さい順に試し、**真の ΔSSE ≤ 0** の最初のものを受理する。
  ΔSSE は d1/d2 の割り当て差分で厳密に計算され、整数演算なので
  許容誤差は 0 でよい。ΔJ が改善でない押し出しは採用しない。
  反復は最大16回。
- **採用した特徴色はロック**: 一度受理された候補は、その後の置換で
  固定色と同様に押し出し対象から外す (試作の予約色と同じ扱い)。
  ロックなしの実装では、synth の星がいったん入った後に −317 という
  微小な真改善のために押し出されて失われた実測があり、その対策。
- **固定色は不変**: PALEN_USE / 固定パレットの色は pal5 の外にあり、
  押し出し対象に構造的に入らない。固定色のビンはヒストグラム・
  応答合計の両方から除外される (選択時と同じ規則)。
- **ON のとき自動選択分は 5bit のまま記録される**: 従来の最終段
  (3bit への引き戻しからの再導出) を AUTO 項目については行わない。
  試作の全数値がこの前提 (いわゆる nosnap) で測られており、ON の
  意味づけをそれに合わせた。§6 の作者確認事項2。

## 3. 変更ファイル

- `source/Convert.h` — `SETTING.EpalHGuard` 追加、
  `cnvEpalColorTo5bit` / `cnvGetPaletteEpalWu` /
  `cnvEpalImprovePalette` の宣言。
- `source/Convert.cpp` — 上記3関数の実装 (UVY 応答・Wu 分割・
  k-means・h 提案ループはすべてここ)。
- `source/WndProc.cpp` — CreatePal の EPAL-N / SC8P 分岐に土台の
  振り分けと改善呼び出し、ON 時の 5bit 記録 (keep_epal)。

- `linux/src/convert_run.cpp` — 同上 (CLI 用 CreatePal)。
  納品ファイルはパレットUI納品時点のファイルに本変更だけを足した

Windows 側 (WndProc.cpp) と Linux 側で CreatePal の変更内容は同一に
そろえてある。

## 4. 検証

作者設定 = SC5P、リサイズ on、アンチエイリアス、サイズモード msx、
拡散 on、係数 0.430、cuterr 0、ディザなし、タイル on。
SSE / far は 555 ヒストグラム上の真の無重み指標 (試作と同じ定義)。

### 4.1 OFF 回帰

回帰バッチ 534 ファイルすべてバイト一致。検証用ツリーのビルドと、
納品ファイル (実験フックなし convert_run.cpp) を組み込んだビルドの
両方で確認した。ON のパレットも両ビルドで一致した。

### 4.2 フルスタック結果 (Wu+k-means+ガード)

| 題材 | 土台 (Wu+km) | フルスタック | 旧 median+guard | 備考 |
|---|---:|---:|---:|---|
| synth SSE | 146,307 | **140,334** | 180,586 | 星カバー率 **100%** |
| synth far>8 | 108 | 111 | 111 | |
| birds SSE | 23,477 | **22,821** | 20,595 | 鳥カバー率 28.6% |
| birds far>8 | 6 | 6 | 5 | |
| fox SSE | 395,859 | **395,859** | 447,695 | ガード受理 0 件 |
| fox far>8 | 390 | 390 | 246 | シアン/緑 0% のまま |
| grad SSE | 613,419 | **613,419** | 667,270 | ガード受理 0 件 |
| photo SSE | 1,194,794 | **1,194,794** | 1,439,252 | ガード受理 0 件 |
| photo far>8 | 3,147 | 3,147 | 5,283 | |

- **synth (星)**: 星 (25,25,25) がそのものとして入り、カバー率
  0% → 100%。プレビューでも灰色の星が視認できる (previews 参照)。
  OFF (従来) では星の位置は補色ディザの斑点になっていた。
- **birds (鳥)**: Wu 土台の時点で鳥に近い色が入りカバー率 71.4% に
  なったが、k-means が SSE 最適化でそれを動かし 28.6% 相当に後退、
  ガードも 28.6% を維持した (SSE は 22,821 まで改善)。
  第2の鳥色 (1,3,8) は最も安い押し出しでも真 ΔSSE が **+723**
  (土台 SSE の約3%) で、ガードは仕様通り拒否した。試作のシード
  ミントが同色を入れられたのは、あちらに受理ガードが無かったためで、
  差分はこの +723 の扱いに尽きる (§6 作者確認事項3)。
  フルスタック SSE (22,821) が旧 median+guard (20,595) より悪いのは、
  土台が良い分ガードの改善余地が小さく、ロック規律も効いているため。
  土台比では悪化していない。
- **fox**: ガードの提案はすべて真ガードで拒否され受理 0 件。
  土台が既に強い題材ではガードは無言になる。SSE は全変種で最良だが、
  far>8 は旧 median+guard (246) より多い (390): 旧方式は土台の
  悪さをガードが far 削減に振り向けていた分で、トレードオフとして
  明記する。シアン帯・缶の緑はカバー率 0% のまま — 均一に飽和した
  台地 (変化ではなく色相の希少性) は本方式の守備範囲外で、予約機構の
  担当という従来の結論通り。
- **grad**: 応答がほぼ 0 で提案自体が立たず、ガードは完全な no-op。
  変化は土台 (Wu+km) の改善のみ。
- **photo**: ガード受理 0 件。土台の改善がそのまま効き、SSE・far
  とも全変種で最良。

### 4.3 SC8P (256色)

土台を Wu+k-means に替えてガードを載せた場合:
fox SSE 64,719 (OFF) → **41,201**、far 25 → 0。
photo SSE 130,451 (OFF) → **85,367**、far 2 のまま。
実行時間の増分は 1変換あたり +0.1〜0.2 秒程度。

### 4.4 固定色の保護

synth で項目0 = 黒 (0,0,0)、項目5 = 白 (31,31,31) を固定して ON:
固定色は両方とも出力に不変で残り、SSE は 639,765 (OFF) → 151,360。
なお星は残り14枠の競合の中で最終的には残らなかった (大きな真改善が
優先された結果。固定色の保護とは独立の現象として報告する)。

## 6. オープン点・作者確認事項

1. **GUI チェックボックス未実装**: Windows 設定ダイアログと
   wx 設定ダイアログに EpalHGuard のトグルを足していない。
   SETTING の保持・CLI での指定・変換への反映は済んでいるので、
   ダイアログに bool 項目を1つ足すだけの状態。
2. **ON 時の 5bit 記録の解釈**: ON のとき自動選択分を 3bit に
   引き戻さず 5bit のまま記録する仕様にした (試作の前提と一致)。
   この解釈でよいか確認いただきたい。
3. **birds 型ケースのガード許容**: 真 ΔSSE +723 (土台比 約+3%) を
   払えば第2の鳥色が入りカバー率が上がる。現行の許容は 0。
   許容を設けるかどうかは作者判断として残す。
4. **Windows VS ビルド確認**が作者側に残る。
5. 実装パラメータ (k-means 上限100回、置換上限16回、種走査上限
   64、応答しきい値 0.25、支持 8、クラスタ半径 5) は決定的動作を
   優先して固定した。調整したい場合は Convert.cpp の
   `cnvEpalImprovePalette` / `cnvGetPaletteEpalWu` 内の定数を参照。
